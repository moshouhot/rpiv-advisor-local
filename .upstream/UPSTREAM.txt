===============================================================================
What the fork changes — "same-model cross-account retry"
===============================================================================

The advisor's completion call uses pi-ai's completeSimple() directly, bypassing
Pi's agent loop. It therefore emits no message_end / assistant_error events, so
account-rotation extensions (pi-multi-account) are blind to advisor failures:
one spent account takes the advisor down while healthy siblings sit idle.

The patch retries the SAME model id on sibling accounts of the same family
(provider name minus the -account-<N> suffix). It NEVER changes the model.

Four edits in execute.ts (full spec in PERSONAL_MAINTENANCE.md § 改动 B):
  B1  import from ./fallback.js; drop errNoApiKey, add ERR_UNKNOWN
  B2  single call -> candidate-chain loop; credentials resolved PER CANDIDATE
  B3  per-attempt order: aborted -> error -> empty-response
  B4  exhausted chain aggregates; single-candidate keeps original wording

Plus the fork-only file advisor/fallback.ts (candidate builder + narrow
classifier + aggregation). Upstream does not ship it, so `cp *.ts` never
clobbers it.

Beyond failover, the fork also adds three subsystems upstream does not have —
per-session opt-in, lab-mode hard block, and /advisor on|off|always. See
PERSONAL_MAINTENANCE.md 改动 C-G. These live in fork-only files
(advisor/session-optin.ts, advisor/lab-mode.ts) plus edits to the 9 patched
files in MANIFEST.md's A-class table.
